# DPCO — Project Overview

## Назначение

DPCO (Deterministic Processing & Cognitive Orchestration) — исследовательская
идея управляющего ядра, которое направляет вычислительные задачи подходящим
исполнителям, проверяет их результаты отдельно от исходного утверждения и
сохраняет происхождение операций.

## Архитектурная концепция

LLM может интерпретировать запрос и сформировать гипотезу или стратегию, но
само управляющее ядро не принимает уверенность модели за доказательство.
Registry описывает возможности исполнителей, Dispatcher выбирает подходящий
исполнитель, Core управляет ограничениями и состояниями, Verifier независимо
проверяет результат, а Ledger сохраняет задачу и исход операции. Для
поддерживаемой области Contradiction Gate отсекает несовместимые уравнения.

Три статуса остаются независимыми:

- `ExecStatus`: `SUCCESS`, `FAILED`, `BLOCKED`;
- `ClaimVerdict`: `TRUE`, `FALSE`, `UNKNOWN`, `NOT_APPLICABLE`;
- `VerifyStatus`: `VERIFIED`, `UNVERIFIED`, `NOT_APPLICABLE`.

## Фундаментальные принципы

1. Статус проверки описывает фактически выполненную процедуру.
2. Успешное выполнение не доказывает правильность результата.
3. Проверка корня отделена от оценки пользовательского утверждения.
4. Ограничения проверяются единообразно при обычном и принудительном выборе.
5. Проверенные результаты и причины отказа фиксируются в журнале.

## Текущее состояние

Состояние: **DPCO PoC v0.1**. Зафиксированный результат в предоставленном
отчёте исполнения: **19 PASS / 0 FAIL** (матрица T01–T10 — 11 проверок, семь
граничных случаев и одна проверка JSONL-журнала). Это результат исполнения в
VS Code Linux-среде с Python 3.12.3, а не утверждение о запуске в другой
системе.

**В PoC пока нет исполнителя для решения систем линейных уравнений.** Gate
может пропустить согласованную систему или заблокировать противоречивую;
согласованная система затем получает `CAPABILITY_GAP`.

## Известные ограничения

- Поддерживаются скалярные уравнения вида `a*x + b = c`.
- Нет исполнителя `solve_system`.
- Точные исполнитель и верификатор используют общую библиотеку `Fraction`.
- Проверка численных результатов зависит от допуска.
- `force_executor` допускает выбор тестового исполнителя; перед production
  использованием этот путь требует ограничения.
- JSONL-журнал не обеспечивает межпроцессную блокировку или защиту от
  подмены.

## Запуск

Из каталога `DPCO`:

```sh
cd DPCO-PoC-v0.1
python3 --version
python3 -m py_compile generate_and_run.py
python3 generate_and_run.py
cd dpco-algebra-poc
python3 -m compileall -q .
python3 tests.py
cat execution_ledger.jsonl
```

Генератор пересоздаёт файлы PoC внутри `dpco-algebra-poc/`; после запуска
тестов журнал дополняется записями.
